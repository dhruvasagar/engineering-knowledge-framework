* Purpose

AI systems are powerful tools, but they introduce risks: incorrect
output, security vulnerabilities, biased suggestions and over-reliance.

This guide defines the practices for using AI safely and responsibly in
engineering work.

* Principles

** Human Oversight is Mandatory

Every AI-generated output that affects production systems, customer
data or engineering decisions must be reviewed by a human.

No AI output is accepted without verification.

** Know the Limitations

AI systems have known limitations:

- They hallucinate: they generate confident-sounding but incorrect
  information.
- They have limited context windows: they lose track of earlier
  information in long sessions.
- They reflect training data: they may suggest outdated or insecure
  patterns.
- They cannot reason about novel situations: they generalise from
  past examples, they do not understand.

** Never Trust, Always Verify

AI is a source of suggestions, not a source of truth.

Verify AI output against:

- Authoritative documentation.
- Test results.
- Security scanning tools.
- Engineering judgement.

* High-Risk Use Cases

Some use cases carry higher risk and require additional safeguards.

** Production Code

AI-generated production code requires:

- Human code review by a peer.
- Automated test coverage.
- Security scanning (Brakeman, bundler-audit).
- Staged deployment with monitoring.

** Security-Sensitive Code

AI-generated code that handles authentication, authorization,
encryption or sensitive data requires:

- Security review by a security engineer.
- Penetration testing if the code is customer-facing.
- Compliance review if regulated data is involved.

** Architectural Decisions

AI-influenced architectural decisions require:

- Documentation of the AI's recommendation and the human rationale.
- Architecture review by a qualified architect.
- ADR documenting the decision, alternatives and trade-offs.

* Prohibited Use Cases

The following uses of AI are prohibited:

- Generating code that will be deployed without human review.
- Generating security-sensitive code without security review.
- Making architectural decisions without human evaluation.
- Generating customer-facing content without editorial review.
- Using AI to bypass security, compliance or quality processes.

* Verification Practices

** For Code

- Compile the code and verify no errors.
- Run the existing test suite.
- Write and run new tests for AI-generated code.
- Run security scanners (SAST, dependency audit).
- Review by a peer.

** For Documentation

- Verify facts against authoritative sources.
- Check terminology against the relevant glossary.
- Verify links are valid.
- Review for tone and appropriateness.

** For Architecture

- Evaluate against the relevant principles (handbook).
- Verify trade-offs are documented correctly.
- Check consistency with existing architectural decisions.
- Review by an architect.

* Over-Reliance Prevention

** Signs of Over-Reliance

- AI-generated code is accepted without understanding.
- AI suggestions are preferred over team discussion.
- Engineering judgement is deferred to AI.
- AI is used for tasks that require domain expertise.

** Prevention Practices

- Use AI as a collaborator, not a decision-maker.
- Always understand code before accepting it.
- Discuss AI suggestions with the team before adopting.
- Regularly audit AI usage patterns.
